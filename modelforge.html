Three separate questions

OBJECTIVE

What should the model learn?

Pretraining learns token prediction broadly. SFT learns from demonstrations. Preference optimization changes which responses are favored.

ADAPTATION

Which parameters can change?

Full fine-tuning updates model weights. LoRA trains added low-rank matrices. DoRA also learns weight magnitudes.

SYSTEMS

How does the run fit?

Precision, quantization, checkpointing, optimizer state, and distributed execution affect memory and throughput. They do not replace an evaluation plan.

SFT is a training objective; LoRA is an adaptation technique. You can perform SFT using LoRA. These are complementary choices, not competing categories.
FOUNDATION

Pretraining & continued pretraining

Predict tokens across a corpus. Continued pretraining starts from existing weights and can adapt domain language; it needs held-out evaluation to detect regressions.

DEMONSTRATIONS

Supervised fine-tuning · SFT

Train against desired responses. Example: a support question paired with a correctly structured answer. Dataset quality and loss masking matter.

PREFERENCES

Direct Preference Optimization

DPO uses chosen/rejected response pairs relative to a reference policy. It optimizes a preference objective without a separately trained reward model.

VERIFIABLE REWARDS

RLVR & GRPO

RL with verifiable rewards can use code tests or answer checks. GRPO estimates relative advantages from grouped samples. Reward design and rollout compute remain critical.

COMPRESSION

Distillation

A student learns from teacher outputs or distributions. Check licensing, teacher errors, evaluation contamination, and performance on the intended task.

RETRIEVAL

RAG is a different lever

Retrieval supplies context at inference time without necessarily updating model weights. Prefer a retrieval baseline when the problem is changing reference information.

MEMORY

QLoRA

Keep the backbone frozen in a 4-bit representation while training LoRA adapters. NF4, double quantization, and paged optimizers are features of the original work.

EXECUTION

Efficient attention & checkpointing

Memory-efficient attention avoids materializing some intermediates. Activation checkpointing saves stored activations by recomputing them during backward passes.

ARCHITECTURE

Sparse mixture of experts

A router activates selected experts per token. Total stored parameters and active compute differ; routing, load balancing, and communication add complexity.

What DoRA adds

V = W₀ + (α / r) BA
W′[j, :] = m[j] × V[j, :] / ‖V[j, :]‖₂

DoRA separates magnitude from direction. In this linear-layer convention, each output row gets one learnable magnitude. The low-rank adapter updates direction.

Explicit mixed-precision Adam-style assumption: 2-byte trainable weights + 4-byte master weights + 4-byte gradients + 8-byte moments = 18 bytes/trainable parameter. Frozen LoRA/DoRA backbone: 2 bytes/parameter. QLoRA: ideal 0.5 bytes/backbone parameter before quantization metadata. Implementation choices can change every subtotal.

Compute is not the trainable-parameter count

Even with frozen backbone weights, activations still move through the model and gradients propagate through its layers. Adapter parameter savings do not translate directly into equal FLOP or training-time savings.

All target matrices are assumed square and equal width. Real grouped-query attention can have smaller key/value projections. The independent base parameter count and adapter geometry are a planning abstraction, not a validated model architecture.

ACTUAL BROWSER COMPUTATION

Fit ŷ = wx + b to five fixed examples. A gradient step changes w and b to reduce mean squared error.

Training points follow y = 2x + 1. Three separate points are used for holdout evaluation only. This noiseless toy problem does not represent an LLM or demonstrate generalization to real-world data.

Loss = mean((wx + b − y)²)
∂L/∂w = 2 mean(error × x)
∂L/∂b = 2 mean(error)
w ← w − η ∂L/∂w
b ← b − η ∂L/∂b
